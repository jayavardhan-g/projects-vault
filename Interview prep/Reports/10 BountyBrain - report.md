## 1. Summary

BountyBrain answers four learner questions over a **local knowledge graph** built from open, bulk-downloadable security datasets:
1. **"Where do I start?"** A learning path for one vulnerability class: weakness → attack patterns (easiest first) → real disclosed reports → practice labs → what to learn next. Each step is a graph edge.
2. **"Explain this vulnerability class."** A tutorial generated by a local LLM from retrieved passages, **citing them by number**. Citation faithfulness is measured.
3. **"How does this weakness relate to everything else?"** A typed, traversable graph over MITRE CWE and CAPEC.
4. **"I ran recon, what should I test next?"** Parse the user's own recon output and produce a ranked, cited test plan for the fingerprinted stack.

It **never scans anything**, and there is no network egress at query time.

**Stack:**
- SQLite via SQLAlchemy for the graph;
- embedded **Qdrant** for vectors, plus **BM25** (`rank_bm25`);
- **RRF** fusion and a **cross-encoder reranker** (`BAAI/bge-reranker-base`);
- embeddings `BAAI/bge-small-en-v1.5`;
- LLM **Qwen2.5-14B-Instruct** served by a local **vLLM 0.27.1** with guided (JSON/choice) decoding;
- FastAPI API, six Streamlit pages.

**Graph [MEASURED]:** **111,896 nodes, 96,805 edges, 7 node types, 8 typed edge tables.** The ontological core is 35,278 nodes and 63,340 edges.

**Evaluations (five suites):**
- retrieval ablation (hybrid + rerank R@1 0.800 vs dense 0.665);
- CWE classification against two gold sets;
- recon-planner ranking vs prior and random baselines (P@1 0.427 vs 0.325);
- tutorial citation faithfulness with an LLM judge calibrated against blind hand labels (κ = 0.75);
- learning-path completeness.

Plus 84 unit tests and an end-to-end run (13/13 API routes, 7/7 UI pages).

## 3. Background (teach first)

### 3.1 Security vocabulary
- **CWE (Common Weakness Enumeration, MITRE):** a taxonomy of weakness *classes*, e.g. CWE-79 XSS, CWE-89 SQL injection, CWE-639 IDOR.
  - Abstraction levels: Pillar → Class → Base → Variant, plus Compound.
  - Relations: ChildOf, PeerOf, CanPrecede.
- **CAPEC (Common Attack Pattern Enumeration and Classification, MITRE):** *how* weaknesses are attacked. Each pattern has an execution flow (Explore → Experiment → Exploit), a required skill level, and links to the CWEs it targets.
- **CVE:** a specific vulnerability in a specific product.
- **CVSS:** a severity score.
- **EPSS:** the probability of exploitation in the next 30 days.
- **Exploit-DB:** a public exploit archive.
- **nuclei-templates:** detection signatures (YAML) labelled with CWE, CVE, CVSS, EPSS and CPE (product).
- **Bugcrowd VRT:** maps bug types to payout priority P1–P5.
- **pentester.land:** an index of public bug-bounty writeups with labels and bounty amounts.
- **Recon:** discovering a target's hosts and technologies (subdomains, ports, tech fingerprinting with httpx/wappalyzer, nmap).

### 3.2 Retrieval
- **BM25:** lexical TF-IDF with saturation and length normalisation. Exact tokens matter (payload strings, CVE ids).
- **Dense bi-encoder:** query and passage embedded separately; cosine similarity. Catches paraphrases.
  - BGE models are **asymmetric**: queries get an instruction prefix and passages don't.
- **Reciprocal Rank Fusion:** score(d) = Σ_runs 1/(k + rank_run(d)), with k = 60. Uses only ranks, so the incomparable score scales of BM25 and cosine don't matter.
- **Cross-encoder reranker:** (query, passage) go through one transformer that outputs a relevance score. Much more accurate, much slower, so only the top-N candidates are reranked.
- **Metrics:**
  - R@k: is the relevant item in the top k?
  - MRR: mean of 1/rank of the first relevant item.
  - nDCG@k: graded gain, discounted by log₂(rank+1) and normalised by the ideal ordering.
  - P@k: precision at k.

### 3.3 RAG faithfulness and LLM judges
- A RAG answer is **faithful** if each claim is supported by the retrieved sources it cites.
- An LLM judge can label (claim, source) pairs. Its reliability must be checked against human labels with **Cohen's κ** = (p_o − p_e)/(1 − p_e), i.e. agreement corrected for chance.

### 3.4 Guided decoding
vLLM (with the xgrammar backend) can constrain generation to a JSON schema or a fixed set of choices. Then "pick a CWE from this shortlist" **cannot** produce an id outside the shortlist.

### 4.4 Entity resolution: the alias table (the hard part)
- Writeups say "IDOR". MITRE says "Authorization Bypass Through User-Controlled Key" (CWE-639).
- **Three alias layers:**
  1. official CWE names;
  2. official `Alternate_Terms`, plus short names inside quoted parentheticals ("('Cross-site Scripting')") and bare ones ("(CSRF)");
  3. **109 hand-curated community terms** that MITRE lacks (IDOR, SSTI, account takeover, subdomain takeover, WAF bypass…).
- In total **1,389 aliases → 969 classes**. These map **93.1%** of vulnerability-labelled writeups onto CWE (up from 76.5% before layers 2–3).
- 22 labels that are not vulnerability classes ("Android", "Cloud", "AI") are excluded from the denominator rather than force-mapped. Force-mapping them would be fabrication [DOC].
- A test asserts every curated alias points at a real weakness. It caught 6 aliases pointing at CWE-840 and CWE-16, which are *categories*, not weaknesses.
- Bug fix `5cc8d85`: **exact alias before substring match**. "SQL injection" → CWE-89, not the Hibernate variant.

## 5. Retrieval (RAG) pipeline

### 5.1 Indexing (`rag/index.py`, `index_corpus.py`)
- **Structure-aware chunking:** fenced code blocks are never split. In this corpus a payload *is* the answer, and half a payload retrieves as noise [DOC].
- Tests check that code fences survive chunking and that chunks never become subsets of one another.
- Chunks are embedded with BGE-small (passage mode) into embedded Qdrant. A chunk cache feeds BM25, so both sides use identical chunks.

### 5.2 `rag/hybrid.py`
- `search(query, top_k=5, mode, candidates=40, flt)` with **four modes**: `dense`, `bm25`, `hybrid`, `hybrid_rerank`. Each stage can run alone, so the ablation is honest [DOC].
- BM25 side: lowercase regex tokens `[a-z0-9_.-]+` (keeps `../`, `cve-2021-…` style tokens), `BM25Okapi.get_scores`, sort, optional metadata filter.
- Dense side: `embeddings.embed_query` (with the query instruction) → Qdrant search.
- **`reciprocal_rank_fusion(runs, k=60)`:** key = (document_id, chunk_idx); score += 1/(60 + rank).
- `hybrid_rerank`: take the fused top-40 and score them with the cross-encoder (`rag/reranker.py`), keeping the top-k.
- Why RRF over score interpolation [DOC]: cosine and BM25 scales are incomparable, and normalising them needs per-query statistics that drift with corpus size.
- [RECON] Code detail: `_model()` is `@lru_cache`d, so a **failed** reranker load is cached as `None` and reranking silently becomes identity for the rest of the process.

### 5.3 Retrieval evaluation [MEASURED]
- **200 held-out queries**, **model-generated from held-out passages** with an instruction *not to reuse distinctive tokens*. Otherwise BM25 wins by construction.
- **Known-item relevance:** a hit counts if it comes from the source *document* (any of its chunks). That under-counts other relevant documents, so absolute recall is a lower bound, but it is identical across arms.
- The query set is committed in `bountybrain/fixtures/`.

| mode | R@1 | R@5 | R@10 | MRR | nDCG@10 | median ms |
|---|---:|---:|---:|---:|---:|---:|
| dense | 0.665 | 0.885 | 0.925 | 0.759 | 0.791 | 39 |
| BM25 | 0.655 | 0.850 | 0.890 | 0.735 | 0.764 | 16 |
| hybrid (RRF) | 0.675 | 0.910 | 0.955 | 0.773 | 0.809 | 56 |
| **hybrid + rerank** | **0.800** | **0.965** | **0.975** | **0.861** | **0.873** | 154 |

- RRF alone adds little at R@1 (+0.01) but helps R@10 (+0.03). The **reranker** gives the big jump (+0.125 R@1) for about 100 ms more.
- Per document type (rerank): writeup R@5 1.000, technique 0.980, article 0.940, weakness 0.940.
- A bug found earlier (commit `3b92ad2`): the nDCG normalisation was fixed.

## 6. CWE classification (assigning a weakness class to text)

**Three strategies plus routing (`ingestion/classifier.py`, `eval/classification.py`):**
- **keyword:** longest-alias lookup; no model; may abstain.
- **embedding:** the nearest CWE by vector.
- **llm:** shortlist the top-12 CWEs by embedding, then the LLM picks one *from the shortlist* with guided decoding. Hallucinated ids are **structurally impossible**.
- **keyword→llm:** use keyword when it fires, otherwise ask the LLM.

**Metrics:** exact accuracy, **hierarchy ±2** (credit within 2 ChildOf hops, so CWE-79 vs its child CWE-80 is a smaller error than CWE-89), macro-F1, **abstention rate** (so abstaining can't inflate accuracy).

**Two independent gold sets, 500 items each [MEASURED]:**

| strategy | nuclei acc | nuclei ±2 | writeup-title acc | writeup ±2 |
|---|---:|---:|---:|---:|
| keyword | 0.398 | 0.444 | 0.402 | 0.426 |
| embedding | 0.210 | 0.314 | 0.330 | 0.412 |
| llm | 0.374 | 0.456 | 0.364 | 0.416 |
| **keyword→llm** | **0.404** | 0.452 | **0.474** | 0.526 |

**Findings:**
- **The shortlist, not the model, is the ceiling.** The gold class is in the top-12 only **45%** (nuclei) / **53%** (titles) of the time. When it is there, the LLM picks it **83% / 69%** of the time. When it isn't, accuracy is 0 by construction. Better candidate retrieval is worth more than a better LLM.
- **A confound found and fixed** (commit `6187c2a`): the 109 curated aliases reached the keyword baseline but were never stored in the graph, so the embedding/LLM shortlists never saw them. After persisting them, the writeup LLM went 0.280 → 0.364 and embedding 0.188 → 0.330. Nuclei barely changed, because template prose rarely uses slang.
- **Caveat [DOC]:** writeup gold labels are derived from the same alias table that the keyword arm uses on titles, which gives keyword free wins. **The nuclei set is the fair comparison**, and there keyword and LLM are close.
- **Conclusion:** keyword is the right default for bulk CWE assignment (fast, free, as accurate). The LLM earns its place writing cited prose.

## 7. Recon planner (`recon/parsers.py`, `recon/planner.py`)

### 7.1 Parsing
`recon/parsers.py` reads the user's own tool outputs and fingerprints technologies per host. A bug fix (`3d4bd23`): CVEs were being parsed one character at a time, and merged assets were mishandled.

### 7.2 Scoring: four signals (`ScoringWeights`, `planner.py:75-98`)
| signal | weight | source | definition |
|---|---|---|---|
| **applicability** | 0.55 | nuclei templates on this product | smoothed conditional P(class \| product) |
| exploitability | 0.15 | max EPSS of matching templates, else CWE likelihood prior | probability of real exploitation |
| weaponisation | 0.05 | Exploit-DB count | log-scaled (saturating at 25) |
| economics | 0.25 | disclosed bounties + Bugcrowd VRT | 0.5·money + 0.3·VRT((6−P)/5) + 0.2·log(writeups, saturating at 60) |

- **Applicability (the fix that mattered)** (`planner.py:290-311`):
  ```
  conditional[c] = (n_c + α·prior[c]) / (N + α),   α = SMOOTHING_ALPHA = 25
  applicability = conditional / max(conditional)
  ```
  - n_c = number of this product's templates detecting class c; N = the total for the product; prior = the global class frequency.
  - α = 25 means "pretend we saw 25 extra templates distributed by the prior". A product with 2 templates falls back to the prior; one with hundreds is dominated by its own evidence (Bayesian / Dirichlet smoothing).
- Applicability carries the largest weight because it is the **only stack-conditioned term**. The others describe a class in general and would re-derive global popularity [DOC].
- Output per recommended class:
  - CAPEC **execution-flow** Explore/Experiment steps, each linked to its pattern;
  - nuclei templates to run (sorted by EPSS, then CVSS);
  - best-paying prior disclosures;
  - disclosed reports that match both the class *and* a technology on the asset.

### 7.3 Planner evaluation [MEASURED]
- **Gold** = a **held-out** nuclei template for the product. 20% of each product's templates are held out *and removed from the evidence pool*. Otherwise the planner would be graded on the very edges it scores with.
- **Baselines:** `random` (shuffled candidates) and **`prior`** (global class frequency, ignoring the fingerprint). **Beating `prior` is the real bar.**

| strategy (400 cases, 147 products) | P@1 | P@3 | P@5 | MRR |
|---|---:|---:|---:|---:|
| planner (value-weighted) | **0.427** | 0.562 | 0.650 | 0.517 |
| planner (likelihood-only) | 0.422 | **0.570** | **0.662** | **0.522** |
| prior | 0.325 | 0.532 | 0.598 | 0.445 |
| random | 0.095 | 0.282 | 0.440 | 0.245 |

- **The first version lost to the prior** (P@1 0.280 vs 0.325). Its applicability was a log-scaled count, which saturates at 1.0 for any popular product, so every ranking was decided by stack-independent terms. The smoothed conditional raised P@1 to **0.427**.
- Value weighting costs a little (P@3 0.562 vs 0.570), as expected: "most likely" and "most worth your afternoon" are different questions. Both are shown in the UI.

## 8. Tutorials and faithfulness (`agent/`, `eval/faithfulness.py`, `prompts/`)

### 8.1 Generation
- Learn page: hybrid-retrieve passages for the topic, add a **graph summary as the last numbered source**, and ask Qwen2.5-14B for a tutorial citing sources as `[n]`.
- Prompts live in `prompts/` and are never inlined in code.
- An earlier web-search tool (Brave) **silently returned nothing without an API key**, so the agent claimed to have searched while grounding in nothing. It was removed rather than left as a stub [DOC].

### 8.2 Faithfulness evaluation (30 fixed topics, through the page's own code path)
1. Split the tutorial into sentences (no model).
2. Check each `[n]` against the provided sources. A number pointing at nothing is a hallucinated citation, detectable exactly: **0.0%**.
3. An **LLM judge** (the same model) reads the cited excerpts, truncated exactly as the generator saw them, and labels each sentence supported / partial / unsupported.
4. **Calibrate the judge against blind hand labels:** 40 sentences per prompt, stratified by the judge's verdict. The hand labels were made by Claude, blind to the judge's verdicts.

| | baseline prompt | current prompt |
|---|---:|---:|
| sentences carrying a citation | 13.2% | 54.5% |
| citations pointing at no source | 0.0% | 0.0% |
| cited sentences judged supported | 15.7% | 42.4% |
| cited sentences judged unsupported | 22.9% | 9.1% |
| cited sentences supported (hand-calibrated) | 38.6% | 59.7% |
| **all sentences cited and supported (hand-calibrated)** | 5.1% | **32.6%** |

| judge vs hand | 3-way agreement | κ | binary agreement | κ |
|---|---|---|---|---|
| baseline prompt | 0.600 | 0.42 | 0.725 | 0.41 |
| current prompt | 0.825 | **0.71** | 0.875 | **0.75** |

- **Root causes of the bad first result [DOC]:**
  - graph facts were given "for framing" with no number, so they were used uncited (one SSRF tutorial attached the class's top bounty, $288,500, to an unrelated example);
  - the citation rules sat *above* about 7k characters of sources.
- **Fix:** make the graph summary the last numbered source and put the rules (with an example) **after** the sources. Tuned on 10 separate dev topics; the 30 test topics were run once.
- **Still wrong:** under half the sentences cite anything; "partial" is a catch-all; safety reminders get tagged with sources.

## 9. Learning path completeness [MEASURED]
- Path = weakness → CAPEC patterns (lowest required skill first) → writeups → labs → next. An empty stage borrows from a parent or child class **and says so**.
- **Learner topics (29):** 86.2% complete, 69.0% without borrowing.
- **All 969 CWEs:** 16.2% complete, because most classes have no writeup or lab.
- Unresolved: NoSQL injection. Incomplete: subdomain takeover, clickjacking, mass assignment, CRLF injection.

## 10. Engineering details worth knowing
- **vLLM traps** (SETUP.md): a flashinfer patch is needed on Python 3.11; `--enforce-eager` by default on Python < 3.12; `ninja` must be on PATH; guided decoding had to be fixed to actually apply on vLLM 0.27 (`83090cd`). `serve_llm.py` picks a free GPU, at 40% memory.
- **Embedded Qdrant takes an exclusive lock** on `data/qdrant`, so the UI and an eval can't run together (or set `QDRANT_URL`). The client is closed deterministically at exit (`c0a8ef2`).
- Exploit-DB has about 460 duplicate ids, handled in parsing and tested.
- README metric tables are **generated from artifacts** by `report.py`, never hand-copied.
- **Tests:** 84 tests with no network or GPU. `test_app_smoke.py` renders every Streamlit page (`streamlit.testing`) and calls every API route with stubs. `e2e.py` runs the real stack.
- **Environment:** mamba env `bountybrain`, Python 3.11.17, torch 2.13.0+cu130, vllm 0.27.1, transformers 5.20.2, sentence-transformers 6.2.0, xgrammar 0.2.8, qdrant-client 1.20.0, SQLAlchemy 2.1.6, streamlit 1.66.1.

## 12. Limitations
- Known-item retrieval relevance under-counts relevant results (lower-bound recall).
- The classification ceiling is shortlist recall (45–53% at 12).
- Faithfulness: only 32.6% of all sentences are cited *and* supported.
- Planner weights are heuristic; gold labels come from nuclei templates (detection coverage ≠ real bug frequency).
- The graph has a large disconnected tail; most CWEs lack writeups or labs.
- The hand labels used to calibrate the judge were produced by Claude, not a human expert.
